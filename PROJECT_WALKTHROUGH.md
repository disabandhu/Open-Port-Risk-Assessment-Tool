# PortShield — Setup, Usage & Results Walkthrough

This guide accompanies the [README](README.md). It explains how to run the application and how to demonstrate each page of the **Open Port Risk Assessment Tool** without changing the security engine or the simulated infrastructure.

## 1. What the project does

PortShield evaluates **configured** open ports, firewall rules and service access policies for a simulated cloud environment. It produces per-port risk classifications, project-specific risk scores, explanations and recommendations. The dashboard is built with Streamlit and displays the current assessment generated by the project modules.

**Important scope limits:** This is a **configuration-based simulation**, not a live cloud inventory, vulnerability scanner or remote port probe. The sample public-IP addresses are illustrative documentation addresses. The risk scores are project heuristics—not CVSS scores or proof of a real-world vulnerability. The separate localhost scanner module is not a dashboard tab.

## 2. Requirements

- Python **3.10 or newer** and an installation of `pip`.
- A desktop browser and a terminal (PowerShell, Command Prompt, Terminal, or VS Code's integrated terminal).
- Streamlit, pandas and ReportLab, installed through the provided `requirements.txt`.
- No cloud credentials, API keys, database, login or live hosts are required for the dashboard demo.

## 3. Installation and launch

1. Download or clone the repository, then open a terminal **inside the project folder** containing `README.md`, `requirements.txt`, `main.py`, and `ui/`.
2. Create a Python virtual environment (recommended):

   ```bash
   python -m venv .venv
   ```

3. Activate it using **one** command appropriate for your terminal:

   | Terminal | Activation command |
   | --- | --- |
   | Windows PowerShell | `.venv\Scripts\Activate.ps1` |
   | Windows Command Prompt | `.venv\Scripts\activate.bat` |
   | macOS / Linux | `source .venv/bin/activate` |

   On some Windows installations, use `py -3` instead of `python` when creating the environment. If PowerShell blocks activation because of its execution policy, use Command Prompt activation or invoke `.venv\Scripts\python.exe` directly for subsequent Python commands.

4. Install all application dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

5. Launch the Streamlit application:

   ```bash
   python -m streamlit run ui/app.py
   ```

6. Open the **Local URL** shown in the terminal (usually **http://localhost:8501**). Use the navigation in the left sidebar. To stop the server, press **Ctrl+C** in the terminal.

**Tip:** Run commands from the repository root; the app loads code from `core/` and `simulation/` using the existing project structure. The first installation needs access to your Python package index; afterward, starting the application normally does not require access to a cloud account.

## 4. Suggested demonstration route

Navigate in this order: **Dashboard → VM Explorer → Risk Findings → Remediation → Reports**. The same simulated VM inventory and assessment form the baseline for these screens; remediation previews do **not** replace it.

### Tab 1 — Dashboard

**Purpose:** Get an immediate overview of exposure and assessment results.

- Metric cards show the total **virtual machines**, **configured ports** and counts of **High**, **Medium**, **Low** and **Review Required** findings.
- The **Risk distribution** chart compares the counts by severity.
- The **Findings by virtual machine** chart compares severity counts across the VM inventory.
- **Priority findings** lists High and Review Required findings with VM, port/protocol, service, firewall/source, severity and score.
- Expand **View full priority finding descriptions and recommendations**, then select a finding to see the underlying policy context, assessment reasoning and recommendation.

**What to verify:** Counts and charts agree with the underlying findings; clicking the priority detail selector changes only the displayed finding.

### Tab 2 — VM Explorer

**Purpose:** Investigate an individual simulated VM and its access rules.

1. Pick a VM from **Select a virtual machine** (the selector also shows its role).
2. Review its **role**, **network segment**, **private IP** and **simulated public IP**, plus the host, VM type and configured port count.
3. Examine **Configured services & firewall rules**. This table includes each configured port's protocol and service together with matching firewall rule source/action; repeated configured rules are shown separately.
4. Review **Assessment findings** for that selected VM.
5. Expand any finding to inspect risk level, score, firewall status, exposure, allowed source, policy compliance, assessment reasons and the recommended action.

**What to verify:** Switching VMs updates both their network context and associated findings; the displayed addresses are illustrative, not evidence of live connectivity.

### Tab 3 — Risk Findings

**Purpose:** Filter and investigate the assessment's per-port findings.

1. Use the **Severity** multiselect to include/exclude High, Medium, Low or Review Required classifications.
2. Use **Virtual machines** to filter by one or more VMs; when none are selected, the VM filter means **all VMs**.
3. Use the search field to match VM name, role, service, firewall source, exposure or recommendation. Search is case-insensitive and treats the entered text literally.
4. Read the filtered finding count and results table (VM, port/protocol, service, firewall/source, severity and score).
5. Choose **Inspect a finding** under **Finding detail** to read the complete context, policy issue (where applicable), reasoning and recommendation.

**What to verify:** The count changes when filters/search change; clearing filters restores the full assessment. An empty match is informational, not an application failure.

### Tab 4 — Remediation

**Purpose:** Safely preview a more restricted firewall source and compare risk assessments.

1. Select a **Virtual machine** and then one of its **Configured ports**.
2. Review the current firewall status and allowed source.
3. Enter a **Proposed allowed source (IPv4 CIDR)**, such as a subnet appropriate to the selected service's access policy. The text box supplies an initial suggestion, but the security engine must validate the proposed change.
4. Click **Apply to copy & reassess**. This is available only when the selected port has one unambiguous ALLOW rule with a supported firewall status.
5. If valid, review the **Before / after comparison** (allowed source, firewall status, exposure, policy compliance, risk score, classification and recommendation). If both scores exist, inspect the reported score reduction.
6. Click **Reset comparison** to clear the preview, or choose another VM/port to assess a different configuration.

**Expected behavior:** The engine checks valid IPv4 CIDR syntax, that the new subnet **strictly narrows** the previously allowed source, and that the new access remains compliant with the service policy. Unsupported or noncompliant proposals display an error or warning instead of silently changing the original. **Only a deep copy of the VM is modified.** No live firewall changes are made, and the baseline assessment remains unchanged.

**Demonstration advice:** Rather than assuming every smaller CIDR will be accepted, choose an eligible VM/port and follow the on-screen validation messages. This avoids presenting an invalid change as a successful remediation.

### Tab 5 — Reports

**Purpose:** Review and export the baseline assessment.

- The metrics summarize the same assessed VM inventory and finding severities seen on the Dashboard.
- **Download findings CSV** exports the current computed per-port findings, including details such as scores, reasoning, network context and recommendations. The downloaded filename is `port_risk_findings.csv`.
- **Download PDF report** exports a paginated assessment with scope, summary, individual findings, recommendations and limitations. The filename is `port_risk_assessment.pdf`.
- **Included assessment data** shows the findings used for export. Expand **Review full exported finding details** to inspect a selected finding.

**What to verify:** Download both files and open them. The **Reports tab exports the baseline**—a temporary remediation preview from Tab 4 is intentionally **not** saved into report data.

## 5. Understanding the results

| Field | Meaning in the UI |
| --- | --- |
| VM / Role / Network segment | The simulated asset and its configured context |
| Port / Protocol / Service | The service endpoint represented in the configuration |
| Firewall status / Allowed source | The evaluated rule outcome and configured source access |
| Exposure | The engine's assessment of configured reachability/exposure |
| Policy compliant / Policy issue | Whether the configured access meets the project's service-specific policy |
| Risk level | High, Medium, Low or Review Required classification from the existing risk engine |
| Risk score | An internal project-specific heuristic; not a CVSS rating |
| Reasons / Recommendation | Assessment explanation and generated guidance for the finding |

**Review Required** identifies results needing further interpretation; do not assume they have a numeric score or treat the label as interchangeable with a validated vulnerability.

## 6. CLI assessment and saved report files (optional)

The dashboard is the main presentation. You can also run the assessment without Streamlit, from the repository root:

```bash
python main.py
```

This prints the summary and a per-port assessment listing in your terminal. To save command-line outputs:

```bash
python main.py --export
```

The optional `--export` command writes **`reports/assessment.json`** and **`reports/findings.csv`** (and may overwrite earlier versions at those paths). These CLI files are distinct from the browser download filenames in the Reports tab.

To run regression tests and the milestone validation script:

```bash
python -m unittest discover -s tests -v
python validate_milestone5.py
```

The validation script writes **`reports/milestone5_test_matrix.csv`** and **`reports/milestone5_summary.json`**. For visual browser checks see [`tests/UI_MANUAL_CHECKLIST.md`](tests/UI_MANUAL_CHECKLIST.md).

## 7. Troubleshooting

| Symptom | What to try |
| --- | --- |
| `python` or `pip` not found | Install Python 3.10+ and ensure it is on PATH; on Windows try `py -3` for the environment setup |
| `No module named streamlit` | Install dependencies in the same interpreter/environment you launch: `python -m pip install -r requirements.txt` |
| Streamlit launch fails | Confirm you're in the repository root and use `python -m streamlit run ui/app.py` |
| PowerShell won't activate `.venv` | Use Command Prompt activation or run `.venv\Scripts\python.exe -m streamlit run ui/app.py` |
| Browser doesn't open automatically | Copy the **Local URL** printed in the terminal and paste it into your browser |
| Port 8501 is busy | Streamlit may show another port; use the Local URL displayed in the terminal |
| Remediation is disabled or rejected | Choose a port with one clear ALLOW rule and propose a *strictly narrower, policy-compliant* IPv4 CIDR |
| PDF report cannot be generated | Verify `reportlab` installed successfully using the project requirements |
| Results don't reflect a remediation preview | This is intentional: the preview uses a temporary copy and baseline reports are unchanged |

## 8. Architecture map (for presentations)

```text
simulation/environment.py   → configured simulated VMs and firewall rules
            ↓
core/assessment.py           → discovers configurations and runs risk analysis
            ↓
core/risk_engine.py          → existing risk scoring and classification
core/recommendations.py     → existing recommendation generation
            ↓
ui/app.py                    → five Streamlit screens and interactions
            ├─ core/remediation.py → simulated copy-based firewall preview
            └─ core/reporting.py   → CSV and PDF downloads
```

The UI styling lives in `ui/styles.css` and `.streamlit/config.toml`. The dashboard presentation does not replace or change the assessment logic, simulation setup or report calculation.
